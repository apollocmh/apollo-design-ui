## Phase 1 完成：项目侦察 + 架构设计 + 开发规范

**任务**：为 `@apollo-design/ui`（Vue 3 版 Ant Design）建立长期开发基础设施。用户明确要求本阶段**不实现组件**。

### 关键事实（实测提取，非记忆）

参考目标锁定 **antd 6.6.4**：

- 48 个运行时依赖，其中 **37 个 `@rc-component/*`**（v6 已从 `rc-*` 迁移命名空间）
- 80 个 `es/` 目录 = 72 个真实组件 + 5 个基础设施 + 3 个别名（`qrcode`/`row`/`col`）
- Token：Seed **34** / Map **140** / Alias **82 own（222 effective）** / Component **70 组、517 个**
- 规模：1148 个 demo、641 个测试文件、314 个快照、75 个 locale
- `@rc-component/util` 被 **61 个组件**引用 —— 真正的地基

### 重要发现

1. **5 个框架无关包可直接复用**：`@ant-design/icons-svg`、`@ant-design/colors`、`@ant-design/fast-color`、`dayjs`、`scroll-into-view-if-needed`（peerDependencies 均为空）。这是达成视觉/算法一致性的最省成本路径。
2. **antd 存在 4 组假循环依赖**（`app↔message↔notification`、`config-provider↔form↔tooltip`、`tooltip↔table↔color-picker`、`select↔cascader` 等），根因是互相 import **叶子模块**（`app/context`、`form/validateMessagesContext`、`table/TableMeasureRowContext`、`color-picker/util`）而非组件本身。
   → 对策：提取 `ui/src/_internal/` 叶子模块，组件之间禁止互相 import 组件目录。
3. **提取依赖时必须区分三类边**：runtime / type-only / leaf。不区分会得到 4 组环，DAG 无法用于任务排序。区分后 82 条运行时边、0 环。
4. antd 6.6.4 的 `es/` 有 3 个别名目录，不识别会导致组件计数错误（75→78）。
5. TypeScript latest 已是 **7.0.2**，但 `unbuild@3.6.1` peer 要求 `^5.9.2` → **锁定 TS 5.9.x**。

### 方法论教训（重要）

1. **不要盲信 lint 的自动修复。** `noConfusingVoidType` 建议把 `() => void | Cleanup` 改成
   `undefined | Cleanup` —— 用 `tsc --strict` 实测后确认这**会破坏 API**：TS 把 `() => {}` 推断为
   `() => void`，而 `void` 不可赋值给 `undefined`，于是连空回调都被拒绝。
   已改为具名类型 + `biome-ignore` 并写明实测结论。
2. **校验项必须做反向测试。** 给 4 个包注入 7 个故障（谎报 completed、PoC 标记为 false、
   未登记的 blockedBy、篡改消费者数、抹掉 layerNotes），确认 7/7 都被捕获后才算数。
3. **`biome-ignore` 必须紧贴目标行**（中间不能隔注释行），且 reason 要在同一行。
