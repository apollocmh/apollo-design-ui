### 本轮最有价值的四条（已进 MEMORY §6）

1. 🚨 **末尾 `...restAttrs` 会覆盖内部同名事件键**（对象展开后者胜）。cascader 把
   BaseSelect 的 `onSearch` / `onOpenChange` 顶掉（内部 `setSearchValue` / `setOpen` 不再跑）；
   switch 的 `onKeydown` 被内部覆盖（模板 `@keydown` 一次都不调）。
   ⇒ **内部持有的事件键必须先从 `restAttrs` 摘掉**。
2. 🚨 **「注释写着正确规则、代码没照做」这类缺口真实存在**（switch #11.2 的
   `interface.ts` 注释、radio README 的 D44「form 未落地」）。⇒ 判据要**跑代码**验证。
3. 🚨 **prop 默认值写成字面量会堵死 ConfigProvider 回退**：
   `direction: { default: 'ltr' }` ⇒ `props.direction ?? ctx ?? 'ltr'` 永远短路在第一支。
   收敛成 `default: undefined` + `mergedDirection`。
4. 🚨 **上游 `useXxx(...)` 在 React 是每次渲染重算 ⇒ Vue 侧必须包 `computed`**，
   否则动态改 `showSearch` / `filter` / `sort` / `limit` 全部无效（cascader #12.3）。

### 一条误报（#10.3 `skipGroup`）

`RadioProps extends AbstractCheckboxProps` ⇒ **类型上**继承到 `skipGroup`，
但 `radio.js` 全文不读（`if (groupContext)` 无条件生效）。SSR 实测：组内 `skipGroup`
那项照样 `-wrapper-checked`，且 React 打印 unrecognized prop 告警。
⇒ 保留声明（类型面对齐 + 从 attrs 摘掉以免多出 `skipgroup` 属性），**不给运行时语义**。

### 测试写法教训

- ⚠️ **空态占位项也算 `menu-item`** ⇒ 断言「搜索结果变空」不能写 `length === 0`
  （实测换成「全不匹配」filter 后是 1 条 disabled 的 `Not Found`）。
  判据改成「没有任何一条是真实候选」。
- ⚠️ 改 `props.direction` 这类**同名键多处**时，`str.replace` 的**子串语义**会误伤
  （10 空格缩进的 `direction: props.direction,` 是 14 空格那行的子串）。
  ⇒ 按行替换并 assert 计数。
