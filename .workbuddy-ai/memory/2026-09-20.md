## 1. 先读上游，不凭记忆写 antd

读了 `/tmp/antd-src/package/es/space/` 与
`/tmp/antd-repo/ant-design-master/components/space/`。三处**读源码才能确定**的事实：

1. **`Item.tsx` 写的是 `{index < latestIndex && separator && <span>…</span>}`** ——
   React 的 JSX 会把 `0 && …` 的求值结果 `0` **当作文本节点渲染出来**。
   于是 `separator={0}` 时，机械基线里两个 `-item` 之间多一个**裸文本节点 `0`**。
   我们用的是真 `if` ⇒ 不产生任何节点。**这是一处真实的行为差异**（登记为 D40 / DEFECT）。
   ⚠️ 它**进不了 L4 的断言**（原因见 §5 与 PITFALLS 120）。
2. **`components/style/compact-item.ts` 里 `borderRadius: 0` 是字面量** ——
   「中间项不要圆角」是结构性重置，上游自己就写死 0，且**不存在**「0 圆角」的 token 可走。
   这条事实后来成了 E10 假阳性修复的依据（§4）。
3. **三个 `ComponentToken` 都是空接口、`prepareComponentToken` 都返回 `{}`** ——
   所以 `tokenStatus` 记 **n/a**，而不是「登记 0 个 token 并声称 done」。
   「确认它确实没有 token」与「登记了 0 个」是两件事。

## 2. 实现：三条最容易被写错的判据

| 判据 | 事实 | 反面 |
|---|---|---|
| 方向优先级 | `orientation` > `vertical` > `direction`，兜底 `horizontal` | `vertical` 的判据是 `typeof vertical === 'boolean'`，**不是真值判断** ⇒「不传」与「显式 `false`」是两条分支 |
| `align` 默认值 | 水平未传折 `center`；**垂直未传保持 `undefined`** | 判据是 `align === undefined`，不是真值判断 |
| `separator` / `split` | 取值用 `??`（传 `''` **不**回落）；**是否渲染**用真值判断 | `separator=""` 与 `separator={0}` 都**不渲染** |

`size` 的两条判据**不同**：预设串走类名（值交给 CSS 变量），非零数字走内联
`row-gap`/`column-gap`（自动补 px），而 `0` / `NaN` / 字符串数字**什么都不加**
（`isValidGapNumber` 的真值短路把 `0` 排除了）。

`latestIndex` 只统计「有内容」的子节点且 `reduce` 初值是 `0` ⇒ 全空时不产生分隔符。
`Space` 用 `keepEmpty` 保留假值子节点的**下标**（对齐 React 的 `traverseAllChildren`），
`Compact` 直接丢弃。

⚠️ 一处必须显式处理：**`VNodeChild` 类型的 prop 要在 `withDefaults` 里显式给
`undefined` 默认值**（PITFALLS 46 / D21），否则 Vue 的 Boolean 强转会把「不传」
变成 `false`，`separator` 的 `??` 判据当场失效。

## 3. 样式：零运行时下的「展开」与随之而来的顺序契约

`space/style/index.ts` 产出 **53 条规则**：Space 16 + Compact 4 + Addon 33。
antd 实测是 **49**（16 + 4 + 29），我们多 **4** 条 —— 差异 D38 的来源：

> antd 用**组件级 CSS 自定义属性**（`--ant-space-addon-*`）做中间变量，
> status 段只改写变量、不额外产规则。我们零运行时（H6）没有这个可覆盖点，
> 于是把 status×variant **展开成复合选择器**。

展开的代价是**特异性拉平**：`.status-error.variant-filled` 与
`.variant-filled.disabled` 都是 (0,2,0) ⇒ **谁赢完全由声明顺序决定**。
所以 Addon 段必须**重排选择器顺序**才能保持层叠等价，这个顺序**就是契约**。

⚠️ 我们**没有** `genCommonStyle` 的 4 条重置（`resetStyle: false`），
Space 的字体/字号/行高 100% 继承上下文 —— 这直接决定了 L6 的渲染容器必须钉死（§6）。

## 4. ⚠️ 越界修了检查器：E10 的两处假阳性（PITFALLS 119）

`registry:check` 报 `❌ E10 space/style/index.ts 存在硬编码圆角: border-radius:`。

**没有**去改样式迁就检查器（那会为了绿灯降低正确性）。逐条查证后确认是**检查器的假阳性**，
而且有两处：

1. `border-radius:0` 被判成硬编码 —— 但 `0` 是结构性方形重置（§1 事实 2），
   上游自己就这么写，且硬造一个「0 圆角」token 会让 B7 判 FAIL。
2. **更潜伏的一处**：`\bborder-radius:\s*(?!var\(|\$\{v\()/` 里的 `\s*` 能匹配**零个**字符
   ⇒ 引擎在「冒号之后、空格之前」求值负向先行，于是 `border-radius: var(--x)`
   （冒号后有空格）**也会被误判**。

改成：

```js
{ re: /\bborder-radius:(?!\s*(?:var\(|\$\{v\(|0(?![\d.])))/, what: '硬编码圆角' },
```

⚠️ 用 `0(?![\d.])` 而不是 `0\b`：后者会让 `0.5em` 也豁免（`0` 与 `.` 之间是词边界）。
逐条验证 12 个用例（`0` / ` 0` / `0.5em` / ` 0.5em` / `6px` / `50%` / `var(--x)` /
` var(--x)` / `${v(...)}` / `border-end-start-radius:0` …）**0 处不符**。

判据（H8）：这处越界**收紧了正确性**，没有放宽验收标准；而且 `genCompactItemStyle`
被 10 个 Compact 消费者共用，不修的话 10 个组件都会撞同一个假阳性。
理由写进 `README.md` §8 与 PITFALLS 119。

## 7. 🚨 最大的一个误判：把「120s 超时」当成「16G OOM」（PITFALLS 121）

构建门禁连续 **3 次** exit 137 / SIGTERM / **日志 0 行**。第一反应是
「16G 机器 OOM 了」（本仓库确实有这条已知问题）。

**没有**就这么下结论，而是做了两个实验：

| 实验 | 结果 |
|---|---|
| `sleep 90` 的**静默**命令 | **活下来**（EXIT=0） |
| 构建门禁 + 每 15s 一次心跳 | 在第 **7** 次心跳（≈105s）后被杀 |

⇒ 临界点落在 90–120s，正是 `BASH_DEFAULT_TIMEOUT_MS = 120000`。
**根因是前台命令默认超时，不是内存。**

显式传 `timeout: 600000` 后，同一条命令一次过：
`检查项 127 | FAIL 0 | PENDING 1 | n/a 50`（`PENDING` 是 `@apollo-design/ui B6`
体积预算，与本轮无关）。

两个**加重误判**的因素（都写进 PITFALLS 121）：

1. `tests/build/run.mjs` **只在最后才打印报告**（前面全是
   `execFileSync(..., stdio:'pipe')` 的静默构建）⇒ 被杀时日志是空的，
   看起来像「进程刚起来就崩了」。
2. 命令里自己起了 `&` 子进程时，文档承诺的「超时自动转后台」**不生效**，
   直接杀**进程组** ⇒ 心跳循环也被一起带走，连 `echo "EXIT=$?"` 都没机会执行。

⭐ 判据：**看到 `exit 137` 先问「这个命令跑了多久」，先加 `timeout` 再谈内存。**
真正的 OOM 有别的指纹：同一条命令**单独跑能过、跟在重命令后面跑才 137**
（本次 `--project a11y` 跟在 `--project dom-contract`（要加载 848 个图标）
后面就 137，单独跑 **114 passed** —— 那才是内存）。

## 8. ⚠️ 一处差点写错的注释：L4 看不见文本节点（PITFALLS 120）

`semantic.test.ts` 里 `separator:zero` 的注释原本写着
「见 `ALLOW` 里的 D25」。查证后发现 **`ALLOW` 里根本没有这一条** ——
`ALLOW` 只有 `prefix-cls:no-props` / `compact:no-props` / `addon:no-props` / `size:negative`。

去读 `packages/test-utils/src/dom-contract.ts:204`：

```ts
return Array.from(template.content.children);
```

注释写得很清楚：「`.children` 只含元素节点：注释（Vue 渲染 `null` 会产生 `<!---->`）
与文本都不进契约。」

⇒ **差异是真的（D40），但这条通道看不见它**。所以它**没有** `ALLOW` 条目 ——
不是因为差异不存在，而是因为 L4 的投影把文本节点过滤掉了。
钉住它的判据落在 **L1**：`index.test.ts`「`separator` 传 `0` 不渲染分隔符」
（断言**无** span，且 `textContent` 不含 `0`）。

⭐ 判据：**别把「没有 `ALLOW`」当成「没有差异」。** 反过来也要小心 ——
一条差异「没被抓住」可能是**观测口径**的问题，而不是断言不够。
