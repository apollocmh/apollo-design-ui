### 关键技术点（下次别再想一遍）

- **TwoTone 图标定义的序列化**：`icon` 是 `(primaryColor, secondaryColor) => AbstractNode`
  **函数**，JSON 化不了。做法是**哨兵色调用 → JSON 序列化 → 把带引号的哨兵换回标识符
  → 包成箭头函数**，并对每个图标做一次「重建函数 vs 原始函数」的等价性自检。
  不用 `fn.toString()`：那会原样依赖上游产物格式（变量名/闭包/压缩），
  上游一改管线就可能吐出引用不存在变量的源码。
- **icons-svg 必须用 `lib/asn`（CJS）而不是 `es/asn`**：上游 package.json 没有
  `"type": "module"`，`es/*.js` 虽是 ESM 语法却被 Node 当 CJS 解析，`import()` 直接
  `SyntaxError`。要在构建期**求值**只能 `require()`。
- **E19 首次运行撞上假阳性**：unbuild **不剥 JSDoc**，而注释里大量出现
  「曾经这样写 `from '@ant-design/icons-svg/es/types'`」的示例文本，被当成真实 import。
  修法：扫描前 `stripComments()`。E11 有同样的隐患，一并加上。

## 组件侧流水线的最终形态（这是「第一个组件」的真实成本）

### 1. `packages/ui` 的构建（`build.config.ts`）

unbuild 的 rollup 管线**不认识 `.vue`**。三条解法都试过，最终选：

- **JS**：往 `rollup:options` 钩子里 push `@vitejs/plugin-vue`（实测在纯 rollup 下可用）
- **类型**：⚠️ **必须关掉 unbuild 的 `declaration`**。`rollup-plugin-dts` 不认识 SFC，
  它会**不报错地**把编译后的 JS 当 `.d.ts` 写进 `dist/index.d.ts` —— 而 B2 只校验路径存在，
  所以这种错误产物能一路绿灯发出去。改由 `build:done` 调 `vue-tsc`
- **CSS**：`build:done` 里 `import('./dist/index.mjs')` 取样式清单，落
  `dist/<component>/style.css` + `dist/index.css`

`vue-tsc` 的三个参数都不能少：`--outDir .dts-tmp` + `--rootDir ../..`（仓库根）
+ 之后 `cpSync('.dts-tmp/packages/ui/src', 'dist')`。
原因：tsconfig 的 `paths` 指向 `../utils/src`，那些文件会进 program ⇒
`rootDir` 只能是它们的公共祖先（仓库根），否则 TS6059。

**替代方案被否决**：「让 paths 指向兄弟包的 dist 类型」会让 ui 的类型产物依赖
**构建顺序**（`tests/build/run.mjs` 原来按目录名排序，ui 排在 utils 前面）。

### 2. `tests/build/run.mjs`：字母序 → **拓扑序**

原实现 `readdirSync().sort()` ⇒ `ui` 排在 `utils`/`theme` 前面，
而 ui 的 `build:done` 要 import 的产物在运行期会 `require('@apollo-design/theme')` ⇒ 必然失败。
同类问题 foundation 层也有（`overlay` 依赖 `portal`/`position`），只是当时恰好已有 dist。

**根 `pnpm build` 走不了这条路**：`pnpm -r run build` 报 `ERR_PNPM_TASK_CYCLE`
（每个包都 devDepend on `test-utils`，而 test-utils 又 depend on theme/utils）。
⇒ **`tests/build/run.mjs` 才是本仓库的权威构建入口**。

### 3. `tests/compat/runner/index.mjs`（此前**不存在**，而 `package.json` 指向它）

落地形态与 Phase 1 设想不同：不做「双运行时进程」，而是
`baseline/<component>.mjs`（React 侧 `renderToStaticMarkup` → 落盘 HTML）
+ vitest 里的 `domContractTest`（Vue 侧渲染 + 两侧同一条归一化流水线比对）。
`icons`（848 图标 / 36 用例）与 `empty`（32 用例）都用它。
顺手给 `icons.mjs` 补了 `--check`（原来它**只会重写基线**，于是 runner 的「校验」会变成「覆盖」）。

### 4. 顺手修掉的两个基础设施工伤

  只要从 test-utils 入口导入任何东西，`instances.size === 0` 恒不成立 ⇒
  **全仓每个组件的 `mountTest` 都必然失败**，且失败信息指向组件（方向完全错误）。

## ⚠️ 本轮最重要的技术发现：Vue 的 Boolean prop 转换（D21）

`React.ReactNode` 在 Vue 侧的对应物是 `VNodeChild`，而 **`VNodeChild` 含 `boolean`**。
SFC 编译器把 `image?: VNodeChild` 解析成运行时类型
`[Object, String, Number, Boolean, null, Array]` ⇒ Vue 的 Boolean prop 转换生效 ⇒
**未传**的 `description` / `image` 被赋成 `false`：

- `description` → `false` ⇒ 描述整块不渲染
- `image` → `false` ⇒ 插画渲染成一个注释节点 `<!---->`

症状极隐蔽：组件「能渲染」，只是少了一块；不报错、不警告、类型检查也过。
是被 L4 的逐节点比对抓出来的。

**修法**：`withDefaults` 里显式声明 `image: undefined` / `description: undefined`
（有 `default` 就跳过转换）。**所有 `VNodeChild` 类型的 prop 都适用** ——
`title` / `content` / `label` / `extra` / `children` / `footer`。

同一根源还让 antd 的 `!(deprecatedName in props)` 判据失效
（Vue 的 props **恒**包含全部声明键）⇒ 改成 `props.imageStyle !== undefined`。

## L6 基建（`tests/visual/`）最终形态

### 七个文件

| 文件 | 作用 |
|---|---|
| `run.mjs` | 入口：vite 打包两侧 → 起本地 http 服务 → Playwright 截图 → pixelmatch 比对 → HTML 报告 |
| `matrix.mjs` | 截图矩阵（variants × themes × viewports）+ `LIMITATIONS`（dark/compact 待 ConfigProvider） |
| `stabilize.mjs` | 禁动画、隐藏 caret、固定 Math.random / Date、waitForFonts、等两帧 |
| `compare.mjs` | sharp 归一化 + pixelmatch + 邻域分析（散点 ≥ 90% → 判抗锯齿噪声） |
| `report.mjs` | HTML 报告（含 LIMITATIONS、逐组结果、三视图并列） |
| `build.mjs` | vite 打包两侧（`base: './'`、`minify: false`） |
| `render/{react,vue}.{html,main.jsx,js}` + `cases/{shared.mjs,react/empty.jsx,vue/empty.js}` | 两侧共用骨架 + 视觉用例 |

### 三种模式

- `both`（默认）：两侧都渲染，最可信；适合「代码改了，确认没坏」
- `baseline`：只渲染 React，写入 `baselines/react/<component>/<id>.png`（**入库 git**，裁决 A）
- `compare`：只渲染 Vue，与入库基线比对（CI 友好，不需 React 环境）

### 必须防的假绿

两侧都白屏时两张空白图 0% 差异 → 按阈值 PASS。`run.mjs` 强制捕获 `pageerror` /
`console.error`，任一侧出错直接判 `FAIL / render-error`，**不比像素**。

### macOS 12 适配

Playwright 1.63 不再为 macOS 12 提供 Chromium（`playwright install chromium` 报
`does not support chromium on mac12`）。`stabilize.mjs` 自动降级：
先试 `channel: 'chrome'`（系统 Chrome），失败再退回自带 Chromium。

### 关键稳定化技巧

- `<link rel="icon" href="data:," />` 塞进两侧 HTML —— 否则浏览器自动请求
  `/favicon.ico` 记一条 404 `console.error`，被「渲染错误」捕获成假失败。
- 静态服务器（`node:http`）不能用 `file://` —— ES module 在 `file://` 被 CORS 拦。
- 截**元素**（`element.screenshot()`）而非整页 —— 两侧外层留白不同，整页比对会把留白差异
  当成组件差异。

## 修了 4 个被 L6 暴露的实现 bug / 缺口

### 1. `theme` 包缺 `./tokens.css` 导出（影响所有消费者）

`packages/ui/src/index.ts`、`empty/index.{zh-CN,en-US}.md`、`ARCHITECTURE.md` 都写着
`import '@apollo-design/theme/dist/tokens.css'`，但 theme 包的 `exports` 只暴露 `.` —
消费者按文档 import 直接解析失败。

**修法**：`scaffold-packages.mjs` 的 theme 定义加 `extraExports: { './tokens.css': './dist/tokens.css' }`
（命名与 ui 的 `./style.css` 同构：不含 `dist` 前缀），然后用
`--force-pkg` 重写 theme 的 package.json。

同时把仓库文档里的 `@apollo-design/theme/dist/tokens.css` 改成 `@apollo-design/theme/tokens.css`
（后续若有人再加文档，先看 `tokens.css` 是否已注册）。

### 2. `Empty` 的 `genEmptyStyle` 选择器漏了 `-empty` 后缀

```js
// 修复前：选择器写出来是 `.apollo { ... }`，选不中根节点（默认 `apollo-empty`）
const cls = `.${prefixCls}`;
// 修复后：`.apollo-empty { ... }`，选中根节点
const cls = `.${prefixCls}-empty`;
```

L6 在「antd 居中 vs 我们左对齐」里立刻抓到（CSS 的 `text-align: center` 选不中元素，
浏览器退回默认 start）。

**同时**：把后代选择器 `${cls} ${cls}-image` 改成顶级 `${cls}-image`，与 antd 的对象子键写法一致
（更贴 antd 6.6.4，且对当前 DOM 也选得中）。

### 3. SVG 颜色走 `var(--apollo-*)` 透明色 vs antd 合成实色 hex

`registry/tools/gen-empty-artwork.mjs` 原把 antd 渲染产物里的 `#f0f0f0` 反查成
`ctx.colors.<role>` 槽位，再让 SVG 的 `fill` 输出 `var(--apollo-color-fill-secondary)`。
但我们的 token 本身就是 rgba 透明色（`rgba(0,0,0,0.06)`），浏览器不会合成实色。

**antd 的设计**：在 SSR 阶段用 `getAsSolidColor(token, colorBgContainer)` 把半透明 token
在白底上合成为实色再写进 SVG（`#f0f0f0`）。主题切换对插画本身不生效（切 dark 时插画颜色
不变，靠外层主题背景接管）—— antd 如此。

**修法**：生成器把 SVG 的 `fill` 直接写 hex 字面量（与 antd 合成结果一致）；`Images.ts` 不再维护
`colors` 槽位。`ROLE_TOKENS` 反查表保留作自检 —— antd 渲染产物里出现新颜色立刻让生成器抛错。

### 4. 没人把 `--apollo-font-family` 应用到 body/html

`tokens.css` 声明了 `--apollo-font-family`，但**没人**把它应用到 `:root` 或 `body` —
浏览器退回默认字体（macOS Chrome = **Times**）。所有含描述文字的组件都被判 block-diff
（0.03% ~ 0.75% 散点）。`no-description` 三档全 0.000% exact，反推差异 100% 在文字。

**修法**：`packages/ui/src/style/index.ts` 新增 `BASE_CSS`（antd `reset.css` 的最小版：
box-sizing + `html, body { font-family: var(--apollo-font-family); font-size: var(--apollo-font-size) }`），
同时嵌进汇总 CSS 与每个组件 CSS（不然只引单个组件 CSS 也会退回 Times）。

## ⭐ 三个「读源码才发现」的事实（写进契约，防后人改回去）

1. **`@rc-component/trigger` 3.10.1 完全不处理 Esc** —— 全 `es/` 目录 grep `Escape|keydown|esc`
   为空。Esc 的监听与 LIFO 栈在 **`@rc-component/portal/es/useEscKeyDown.js`**，
   trigger 只在 `index.js:232-236` 消费 `onEsc({top})`：`if (top) triggerOpen(false)`。
   栈是**按开启顺序**的 LIFO；**每个**成员都收到回调（不是只通知栈顶），靠 `top` 区分；
   `compositionend` 后 **200ms** 内的 Esc 被丢弃（IME 锁）。
   归属裁决：放 **overlay**（`portal-contract.md` §3.6 已把 Esc 排除出 portal，
   理由是 Modal 的 rationale「Esc 属交互语义」；overlay 正是 L2 交互语义包）。

2. **antd 的 z-index 不是 LIFO 栈** —— `useZIndex` 是「组件类型偏移 + 嵌套上下文累加」
   （container +100 / consumer +50），且**最外层浮层不设 z-index**（`result[0]` 为 undefined，
   靠 DOM 顺序决定层叠）。
   ⇒ `packages/overlay/README.md` 里「堆叠：与 portal 的 z-index 协调，后开的浮层在上层」
   这句**有两处错**。z-index 归 `portal`；本包唯一的栈是 Esc 栈。**两者是独立机制，别混。**

3. **Vue 的事件 prop 名必须全小写**（`onMouseenter` 而不是 `onMouseEnter`）——
   runtime-dom 的 `parseName` 会 `hyphenate(name.slice(2))`，React 风格会被解析成
   `mouse-enter` / `pointer-enter` / `touch-start` / `context-menu` / `pointer-down`，
   **静默失效**（不报错、不警告）。只有修饰符后缀（Once/Capture/Passive）保留大写。
   实测踩到：18 个 L2 用例全红，改完命名全绿。已写进契约 §6.1。

## 实践坑（下次直接抄）

- **`setOpen` 的默认延迟**：rc 是 `triggerOpen(nextOpen, delay = 0)`（**同步**），
  但 hover/focus 显式传的 `mouseEnterDelay` 可能是 `undefined` ⇒ `setTimeout(NaN⇒0)`（**下个宏任务**）。
  两个入口必须分开：内部 `triggerOpen(next, delay)` 原样传；对外 `setOpen(next, delay = 0)`。
  用默认参数会吃掉 `undefined`，把 §3.2 的时序差异抹平。
- **变异脚本会 OOM**：一次跑 5 个变异 × 3 个测试文件，第二轮就被 SIGKILL（exit 137），
  而且**结果误报成"漏网"**。必须**一个变异一次 Bash 调用**，只跑必要文件。
  变异后 `cp` 恢复也可能失败 —— 收尾要 `grep` 确认无残留（本轮 esc-stack.ts 就残留了一处）。
- **覆盖率别从 `'..'` 导入**：`index.ts` 是纯 re-export，v8 记 0%，把整包拉到阈值以下。
  测试要直接 import 具体模块（`../use-overlay`、`../actions`）。
- **`coverage.all` 默认 true**：在根跑单包覆盖率会把**其它包**的 src 也计进来，
  `All files` 永远不达标 —— 那是假象。看**按包名聚合的单文件行**才是真实值。
  包内 `cd packages/x && vitest run` 会丢根配置（25 个用例失败），**必须在根跑**。
- **两个 overlay 实例必须在同一个 app 内**：分开 `mount` 会得到两个独立 app，
  `useId()` 都从 0 开始 ⇒ `escId` 撞车 ⇒ Esc 栈幂等 push 后只剩一个。
- 分支覆盖率最后 3 个点靠：shadow host 分支（把宿主 mount 进 `attachShadow` 的 slot）、
  非 Node 目标（`window.dispatchEvent` 时 `composedPath()[0]` 是 window）、
  targetRef 为空（刻意不绑 ref）。另外**删掉两条不可达分支**比硬凑测试更划算
  （`!canUseDom` 由 escStack 自己保证；`?? window` 兜底替掉 `if (!win) return`）。
