### 代码改动

- **`packages/utils/src/color/`（新）** —— 上游两个颜色包的移植落点：
  - `Color` 类（`@ant-design/fast-color` 的 FastColor 等价物）
  - `generatePalette()`（`@ant-design/colors` 的 generate 等价物）
  - **放在 utils 而不是新开包**：依据 R2 例外条款，utils 已是 L0 公共底座
    （icons/motion/portal/… 都依赖它），新开第 14 个包会把「只建必要数量」往坏方向推
  - utils **只放算法不放色值**（R3）
- **`packages/theme`** —— 6 个文件换成 `@apollo-design/utils` 的 `Color` / `generatePalette`；
  **顺手删掉了 antd 的「预设色快路径」**（实测 13 个预设色 `generate(seed)` 与
  `presetPalettes[同名]` 逐位相同，快路径只是省一次计算；删掉后
  `presetPrimaryColors.pink = magenta` 那处**对导入模块就地赋值**也没了，函数变纯）
- **`packages/icons`** —— 生成器改为**构建期求值 + 内联字面量**；`types.ts` 不再 re-export
  上游类型；`two-tone-color.ts` 用 utils 的 `generatePalette`
- **`registry/dependencies.json`** —— `strategyLegend` 加 `generate` / `port` 两个策略；
  三个 antd 条目从 `reuse` 改为 `generate`（icons-svg）/ `port`（colors、fast-color）

### 关键技术点（下次别再想一遍）

- **TwoTone 图标定义的序列化**：`icon` 是 `(primaryColor, secondaryColor) => AbstractNode`
  **函数**，JSON 化不了。做法是**哨兵色调用 → JSON 序列化 → 把带引号的哨兵换回标识符
  → 包成箭头函数**，并对每个图标做一次「重建函数 vs 原始函数」的等价性自检。
  不用 `fn.toString()`：那会原样依赖上游产物格式（变量名/闭包/压缩），
  上游一改管线就可能吐出引用不存在变量的源码。
- **icons-svg 必须用 `lib/asn`（CJS）而不是 `es/asn`**：上游 package.json 没有
  `"type": "module"`，`es/*.js` 虽是 ESM 语法却被 Node 当 CJS 解析，`import()` 直接
  `SyntaxError`。要在构建期**求值**只能 `require()`。
- **E19 首次运行撞上假阳性**：unbuild **不剥 JSDoc**，而注释里大量出现
  「曾经这样写 `from '@ant-design/icons-svg/es/types'`」的示例文本，被当成真实 import。
  修法：扫描前 `stripComments()`。E11 有同样的隐患，一并加上。

### 有意保留的差异（已登记）

- **不支持 CSS 颜色名**（`red` / `aliceblue` …）。上游 `FastColor` 内置 148 个名字的查表，
  那是色值数据，放 L0 违反 R3。Token 全是 hex / `rgb()` 记法，不影响已知路径。
  断言在 `color.oracle.test.ts`。

### 顺手修正的一处既有文档错误

`palettes.ts` 旧注释写「暗色下 `gold-10` 拿到亮色值（#faedb5 应为 #613400）」——
两个值标反了。实际：亮色 `gold-10` = `#613400`，暗色 = `#faedb5`，
当年的事故是暗色拿到了亮色的 `#613400`。新回归用例 `palettes.test.ts` 按正确取值钉住。
