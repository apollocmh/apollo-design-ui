## rc-drawer 内核的结构（已读全，下一轮直接照此实现）

`DrawerPopup.js`（264 行）的渲染骨架：

```
<div class="{p} {p}-{placement} [rootClassName] [{p}-open] [{p}-inline]"
     style={...rootStyle, zIndex} tabIndex={-1} ref={panelRef}>     ← panelRef = 容器（给 useFocusable）
  ├─ CSSMotion(key="mask", ...maskMotion, visible = mask && open)
  │    └─ <div class="{p}-mask [motion] [classNames.mask] [maskClassName]"
  │           style={{...motion, ...maskStyle, ...styles.mask}}
  │           onClick={maskClosable && open ? onClose : undefined} />
  └─ CSSMotion(key="panel", ...motion(placement), visible=open, forceRender,
  │            onVisibleChanged=afterOpenChange, removeOnLeave=false,
  │            leavedClassName="{p}-content-wrapper-hidden")
       └─ <div ref={wrapperRef}
       │        class="{p}-content-wrapper [isDragging && -dragging] [classNames.wrapper] [motion]"
       │        style={{...motion, ...wrapperStyle, ...styles.wrapper}}>
       │     ├─ resizable && <div {...dragElementProps} />        ← 拖拽手柄
       │     └─ <DrawerPanel id containerRef=motionRef prefixCls
       │            className={clsx(className, classNames.section)}
       │            style={{...style, ...styles.section}}
       │            {...pickAttrs(props, {aria:true})} {...eventHandlers} />children
       │        （或 drawerRender(content)）
```

关键判据：
- **尺寸**：`isHorizontal = placement === 'left' || 'right'`；
  `mergedSize = size ?? (isHorizontal ? width : height) ?? currentSize ?? defaultSize ?? (isHorizontal ? 378 : undefined)`
  ⇒ 水平方位写 `wrapperStyle.width`，垂直方位写 `height`（都过 `parseWidthHeight`）。
- **push**：`push === true ⇒ {}`；`false ⇒ { distance: 0 }`；`pushDistance = push.distance ?? 父 context ?? 180`；
  被推时按方位 `translateY(±d)` / `translateX(±d)`（top 正、bottom 负、left 正、right 负）。
- **父推挤链**：`DrawerContext` 提供 `{pushDistance, push, pull}`；子 popup 在 `open` 时
  `parentContext.push()`、关闭/卸载时 `pull()` ⇒ 嵌套 drawer 会逐层推开。
- **mask**：`visible = mask && open`；点击关闭条件 `maskClosable && open`。
- **事件**：`onMouseEnter/Over/Leave/Click/KeyDown/KeyUp` 透传；`onFocus` 先过 `ignoreElement(e.target)`
  （焦点陷阱的「忽略外部元素」逻辑）。
- **属性分流**：`pickAttrs(props, {aria:true})` 给面板、`pickAttrs(props, {data:true})` 给 wrapper
  （本仓用 `packages/utils` 的 `pickAttrs`）。
- 还有两个子 hook 要一起移植：`es/hooks/useDrag.js`（97 行，resizable 拖拽）、
  `es/hooks/useFocusable.js`（17 行，焦点陷阱 + 外部忽略）。

### ⚠️ 发现 1：本仓 `Portal` 的「内联模式」是坏的（`getContainer: false`）

`packages/portal/src/use-portal.ts` 两处对 falsy spec 短路：
- 初始化 `getContainer ? resolveContainer(getContainer(), getDoc()) : null`
  ⇒ `false` 被当成「没有容器」得到 `null`（rc 的 `getPortalContainer(false)` 返回 **`false`**）；
- `reResolveContainer` 里 `if (!getContainer) return;` ⇒ `false` 永远不解析。

⇒ 该路径下**恒假 ⇒ 内容整个不渲染**。rc 的对应判据是 `useDom(mergedRender && !innerContainer)`
+ 容器为 `false` 时**内联渲染**（`!false` / `!undefined` 都为真）。

⭐ **我试过直接改这两处：portal 的 12 条既有用例立刻红** ⇒ 这条路径牵着
`defaultContainer` 的 append 门控（`shouldAppend = mergedRender && !innerContainer`），

## ⚠️ 更正上一条：「Portal 内联模式是坏的」是**误判**（我的锅，记下来避免下次重犯）

上一条记的「`getContainer: false` 时 Portal 内容整个不渲染」**不成立**。实测（探针脚本）：

```
<!--teleport start-->
<div class="apollo-drawer apollo-drawer-right apollo-drawer-open" tabindex="-1">
  <div class="apollo-drawer-mask apollo-drawer-mask-motion-appear ..."></div>
  <div class="apollo-drawer-content-wrapper apollo-drawer-panel-motion-right-appear ...">
```
**内联模式工作正常**。我当初误判的根因是**两个测试写法问题**：
1. **没等 tick**：`mergedOpen = mounted ? open : false`（首帧不开门）+ Portal 的
   `mergedRender` 走的是 `watch` ⇒ 挂载后还要 `await nextTick()` 才渲染出来。同步断言
   看到的是空 DOM ⇒ 被我当成「Portal 坏了」。
2. **断言查错了地方**：用 `getContainer: () => container` 时内容 Teleport 到容器里，
   `wrapper.find(...)` 恒空（要查容器）。改用 `getContainer: false`（内联）后
   `wrapper.find` 就正常了。

⭐ **教训**：把「断言查不到元素」直接归因成「底层组件坏了」之前，先做**最小探针**
（打印 HTML）—— 这次一条探针就推翻了结论。我也因此**没有**去改 portal 的既有实现
（那条改动确实会让 12 条既有用例红，但根因是错的，改了就是白改）。

### ⭐ 本轮最有价值的五条坑（已登记 PITFALLS 178–185）

178. **`setup()` 里不能创建带 `ref` 的 vnode** ⇒ `useModal` 的 holder 实例走 `onReady`

180. **动效名前缀是 `rootPrefixCls`**（`apollo-zoom`），不是组件前缀 ⇒ 写错动效静默失效。
181. **`Skeleton` 是 `inheritAttrs: false`** ⇒ 传 `className` prop，`class` 被静默丢弃。
182. **`h()` 的 children 重载不收 `null | undefined`**（`VNodeChild` 含它们）⇒ 包数组。

184. **手工改 `registry/components.json` 要用 JSON 往返 + 差异校验**（行扫描法静默失败）。
185. **`as unknown as PropType<unknown>` 会让 vue-tsc 把 prop 推断成 `undefined`** ⇒
