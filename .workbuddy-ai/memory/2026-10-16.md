## 本轮踩坑（都在代码注释里有完整「为什么」）
1. **router 必须显式传 base**：vite-ssg 是 `createWebHistory(routerOptions.base)`，
   缺省 `/` ⇒ 部署到子路径后所有路由水合后落到 catch-all 404。`main.ts` 传 `base: import.meta.env.BASE_URL`。
2. **组件样式必须显式 `import '@apollo-design/ui/style.css'`**：没有 cssinjs 运行时，
   漏了它 demo 能跑但全是裸 HTML（很隐蔽）。vite alias 是**前缀**匹配，
   `@apollo-design/ui/style.css` 必须排在 `@apollo-design/ui` 前面并指向 `packages/ui/dist/index.css`。
3. **dirStyle 用 flat**（`components/button.html`）：nested 的 `button/index.html`
   GitHub Pages 认但 **vite preview 不认**（只有尾斜杠才命中）⇒ 选能在本地被证伪的那种。
4. **`build.cssMinify: 'esbuild'`**：Vite 8 默认 lightningcss 会拒绝组件库 collapse 样式里
   `transition: A !important, B !important`（非法 CSS，antd 上游无 !important）⇒ 组件侧缺陷 D1（见 /tmp/issues/ledger.md）。
5. **frontmatter 数字标量**：demo `title: 403` 被 yaml 解析成 number ⇒ 搜索打分 `.toLowerCase` 崩、
   整个 SearchModal 白屏。归一化在 `frontmatter.mjs` 收口（`asText`），搜索侧另有 `safeText` 双保险。
6. **jsdom 没有 `scrollIntoView`** ⇒ tests/setup.ts 补桩（环境缺口，不改组件）。
7. **teleport 内容不在 wrapper 里** ⇒ 测试用 `document.body.querySelector`，不要 stub 掉 Teleport。
8. **真实 demo 动态 import 在 jsdom 首次 ~8s**（拉起整个 @apollo-design/ui 模块图）⇒
   用 `waitUntil` 轮询，不能固定 flushPromises 次数。
9. **`buildManifest` 会被 vite.config 调多次**（includedRoutes + onFinished）⇒
   模块级 notes/problems 数组每次入口必须清零，否则提示重复累积。
10. **CLI 加了 `--if-missing`**：`.generated` 齐全就跳过（全量 ~26s）。
    `pnpm --filter @apollo-design/docs test` 已串上它。

## hover 浮层消失修复（20:15-21:00，#ea0cbf6c）

用户报告：所有 hover 触发的菜单/popover，鼠标一移过去就隐藏。

排查：Playwright 实测复现（dropdown/popover/tooltip/cascader 全部失败）→
事件时序追踪发现浮层从未收到 mouseenter → 逐步收敛到
`overlay.popupRef` 恒为 `null`（全仓只有 overlay 自己的测试绑过它，
trigger.ts 只绑了自己的 popupEle）⇒ hover 保活与外部点击判定的
`popup.contains(...)` 恒 false。

修复：trigger.ts 新增 `setPopupEle()` 唯一写入口，ref 回调 + motion
prepare 钩子都走它，同步两个 ref。回归用例已验证回退即红。

测试中段插曲：tooltip 一度看似仍失败，实为 Playwright 分步移动的
CDP 往返开销（20 步 ~700ms）耗光 0.1s leave 窗口的工具假象；
单步 move / 直接派发 mouseenter 下四类浮层全部通过。

验证：829 unit + 2207 types + biome 全绿；真实浏览器确认
dropdown/popover/tooltip/cascader「移入保持、停留保持、移出关闭」，

## dropdown 点击菜单项不关闭（21:15-21:50，#fee81a58）

用户：dropdown 菜单点击后应该隐藏（antd 行为）。

排查：先核上游逐字源码 `es/dropdown/dropdown.js:149-157` ⇒ antd 是
「通知(source:'menu') + setOpen(false)」两步；本仓 Dropdown.ts 注释却明写
「只通知不改内部 open」（为 Issue #21 的 Table 多选语义），漏了第二步 ⇒
非受控（不传 open）时 emit 无人接收、内部 open 仍 true ⇒ 点菜单项不关。

修复：onMenuClick 两步都做，但用 `suppressNotify` 抑制 setValue 的默认通知 ——
因为本仓 useControlledValue 把通知绑在写值上，直接照抄会补发 source:'trigger'，
而 Table 的 onDropdownOpenChange 只认 trigger ⇒ 多选过滤一点就消失（#21 回归）。

验证：unit 6911（docs/search 有 2 条既有 unhandled rejection：jsdom 缺
scrollIntoView，与本次无关）+ dom-contract/a11y/theme 3792 + types 2207；
真机（vite dev 4478 + Playwright）：dropdown 页 hover/click 两种触发点菜单项
均 leave→hidden ✅；Table 页过滤下拉点选项仍显示 ✅（多选语义未被破坏）。
回归用例已回退验证变红。同步更正 table/README.md §5.3 过期描述。

## color-picker「点外面不隐藏」（22:20-23:00）

现象：所有走 Trigger 的浮层里，**触发器是组件 vnode** 的那批（ColorPicker 的
ColorTrigger / TriggerHost、`<Button>` 触发器）点浮层外面不关闭。

排查：真机（4477 preview + 4478 dev）复现；Select（触发器是元素 vnode）对照正常
⇒ 定位到组件 vs 元素差异。jsdom 复现时抓到
`TypeError: host.contains is not a function` ⇒ overlay 的
`inPopupOrChild()` → `containsOrIs(target, ele)`：Vue 的 ref 在**组件 vnode** 上
给的是**组件实例**，而 `overlay.targetRef` 契约是 `Ref<HTMLElement|null>`
（use-overlay.ts 头注明写）⇒ 外部点击的 mousedown 处理器抛异常 ⇒ 整体失效。

修复：trigger.ts 新增 `resolveTriggerElement()` + `setTargetEle()` 唯一写入口，
`ref: setTargetEle`（归一 `$el`）；`targetElement` 简化为 `overlay.targetRef` 别名
（此前只在**读取侧**归一，overlay 自己读的仍是实例，不够）。

回归（两条，均已回退验证变红）：
- trigger.test.ts：组件触发器 → `nativeElement()` 是元素 + 点内部不关 + 点外部关闭
- color-picker/index.test.ts：点触发器打开 → 点外部关闭（`-hidden` 或 `-leave`）

验证：unit+dom 6913（红灯仍是既有 3 条：demo-preview aria-busy 5s 超时 +
search.test 2 条 jsdom 缺 scrollIntoView；并行跑时 demo-preview 会多红一条
「真实示例渲染…」属负载超时，单跑即绿）；types / biome 待跑；真机（4478 dev）：
面板对齐到触发器正下方 ✅（证明 targetRef 真是元素）、点面板内部不关 ✅、
点外部关闭 ✅、再点触发器 toggle 关 ✅、Esc 关 ✅；popover 页 <Button> 触发器
点外部也关 ✅。
