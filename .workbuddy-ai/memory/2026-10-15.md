## 续：清掉 `test:build` 的两处既有红灯（commit `d152fd32`，用户令「解决问题」）

### B1 docs `vitepress: command not found` —— **是真缺陷，修门禁**

- 门禁 `checkBuild` 用 `/bin/sh -c <script>` 跑包自己的 `scripts.build`，但只把**根**
  `node_modules/.bin` 前置到 PATH。pnpm workspace 下**每个包有自己的 `.bin`**，
  `vitepress` 只存在于 `packages/docs/node_modules/.bin` ⇒ exit 127，并连带 B2 被 SKIP。
- 真实 `npm/pnpm run` 会把**包自身及各级父目录**的 `node_modules/.bin` 都放进 PATH
  ⇒ 门禁少了「包自身」这一级。改 `[包自身, 仓库根, 原PATH]`；`unbuild` 存在性检查
  同步放宽到「任一处有」。
- 效果：docs B1 PASS，**B2 由 SKIP 转实测**，检查项 148 → 151（多出的 3 项即 docs 的 B1/B2 相关）。
- 🚨 这是「门禁拼的环境 ≠ 真实环境」这条教训的**第三次应验**（前两次：2026-10-07 的
  `unbuild` 不带参数、ui-tree-shaking 的 D 项）。凡门禁自己拼命令/环境，都要问「真等价吗」。

### B6 `app 125.7KB > 预算 9KB` —— 上调预算（**技术原因**）

- 严格按 `budget.json` 自述公式 `ceil(measuredKb * 1.5 + 5)`：`ceil(125.7*1.5+5) = 194`
  ⇒ 只改 app 一条（9→194，measuredKb 2.2→125.7），**未人工挑数**，其余 72 条保持原值。
- **先量化再定**（临时探针按模块归属拆解，用完即删）：modal 52 + notification 30 +
  message 5 = 87KB 是 App 契约本身（`useMessage`/`useModal`/`useNotification`，#40 接线）；
  modal 又必然传导 skeleton 20KB（`loading` 占位）与 button 15KB（footer）。
- **核上游确认为同源**（不是本仓摇树缺陷）：antd `modal/Modal.js:20` 同样是
  `import Skeleton from '../skeleton'`（`Modal.js:254` 用于 `loading ? <Skeleton/>`）。
