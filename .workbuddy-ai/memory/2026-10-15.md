### #56 的关键：往 children 里塞内容是**死路**

- 核上游逐字源码：`BorderBeamEffect.js` = `createPortal(el, hostDom)`，
  `!isHTMLElement(hostDom) ⇒ null`；`BorderBeam.js` 返回 `React.Fragment(childNode, effects)`。
  ⇒ 本仓「把 Effect 并进宿主 children」的两条死结：slots 对象退化成 ARRAY_CHILDREN（内容丢）、
  **组件没有 `default` 插槽时无处注入（Effect 静默消失）**。
- 正解：宿主 vnode 只用来**透传 attrs + 注入用户 ref**，`first.children` **原样回填**，
  Effect 交给 `<Teleport :to="hostDom">`。由此与上游**逐字等价**，README §2 的差异项
  从「PLATFORM（实现形态，带已知边界）」改成「逐字等价」。
- 三条配套：① 根**恒为** Fragment（形态翻转会让 Vue 整棵重挂，宿主组件状态与 DOM 全丢）
  ② `to` 传**元素对象**（选择器解析不到组件自己渲染出来的宿主）
  ③ `resolveHostDom`：非 `HTMLElement`（纯文本 ref / 多根组件 `$el` 是锚点文本节点）⇒ null。

### #52 masonry `items` —— 本仓**比上游更糟**（半更新态）

- 上游 `useState([]) + useEffect(() => setMergedItems(items || []), [items])` 是引用比较
  ⇒ 原地 push 完全不更新（观感 = 「没反应」，两条通道都停）。
- **本仓实际是「DOM 更新了、布局没更新」**：`mergedItems` 存的就是调用方那个响应式数组
  **本身**，`motionKeys = mergedItems.value.map(...)` ⇒ 遍历读到 `length` ⇒ DOM 跟着多渲染
  出 item；但 `watch([mergedItems, columnCount], collectItemSize)` 因引用未变**不重测量**
  ⇒ 新 item 没有位置（`top: undefined`、列号 0，视觉上堆在左上角），且 `collectLayout`
  要求「**全部** item 有位置」才写 `itemColumns` ⇒ `onLayoutChange` 整轮停在旧载荷。
- 修法两条配套，**缺一不可**：① 依赖探针 `itemsSignature()` 逐条读 `length`/`key`/`column`
  返回**字符串签名**（内容同 ⇒ 字符串同 ⇒ `Object.is` 判未变 ⇒ 不自激）；② `syncItems()`
  赋值**浅拷贝** `[...props.items]`（不拷贝 = 赋同一引用 ⇒ `shallowRef` 不触发 ⇒ 链条仍断）。
- 🚨 **刻意不用 `{ deep: true }`**：`item.children` 是 `VNodeChild`（递归类型，含
  `el`/`component` 等成环引用），深遍历既贵又危险。
- 保留边界：普通（非响应式）数组无数据源；`children`/`data` 变化走 `fresh`（item 级 RO）。

### #54 affix 监听重绑 —— 「有界 ≠ 无代价」

- 上游依赖集 `[target, affixStyle, lastAffix, offsetTop, offsetBottom]` 混了三类东西：
  **绑定目标** / **固钉状态** / **位置计算参数**，后两类都不影响「绑到谁、绑什么」。
  而 `affixStyle` 每次 `measure()` 都是**新对象** ⇒ 滚动期间**每帧**白跑一轮
  `removeListeners() + addListeners()` = **14 次 DOM 调用**（7 事件 × remove + add）。
- 修法三条：① `addListeners` **幂等短路**（目标未变 + listener 未变 ⇒ return；
  `lazyUpdatePosition` 是节流函数、引用稳定 ⇒ 判据可靠）；② 依赖收窄为
  `[() => props.target]` + `flush: 'post'`；③ `prepareMeasure()` 收尾**补挂** ——
  上游靠「`affixStyle` 每次变都重绑」**无意中**获得「target 未就绪 ⇒ 后续重试」的能力，
  收窄依赖后必须显式保留 ⇒ 用**一次引用比较**换 14 次 DOM 调用。
- 📌 **方法沉淀**：这类「性能/契约核查」issue，光证明「有界、不泄漏」不够，还要问
  **「每次触发的代价是什么、触发频率多高、触发源是否真的相关」**。
