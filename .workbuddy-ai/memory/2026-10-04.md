## 🚨 本轮最贵的两条坑

### ① `tailor` 不传 ⇒ 表头被撑到 209px（size-mismatch 154px）

上游 rc `VirtualTable/index.js` 渲染 `<Table tailor .../>`。`tailor` 让 `useColumns`
拿到 `scrollWidth`，从而 `useWidthColumns` 把**「无 width 的列」按剩余宽度填满**
（antd colgroup 实测 `…,430,430,430,…`）。本仓 antd 层原先没传 ⇒ `scrollWidth=null`
⇒ 那些列宽 `0px` ⇒ `table-layout: fixed` 下标题换行 ⇒ 表头 209px、整表高 674 vs 520。
**判据**：`node tests/visual/debug/dump.mjs react table virtual` 比两侧 `<colgroup>`。

### ② `FixedHolder` 的 table 宽度是**裸数字**（Vue 不做 px 补全）

`width: props.scrollX`（=2000，number）⇒ Vue 的 `setStyle` 不补 px ⇒ **整条声明被丢弃**
⇒ 表头 table 宽退回 auto（710）⇒ 与 `tailor` 的坑叠加。修成
`typeof number ? \`${n}px\` : n`。**这是 PITFALLS 327-330 同族坑的又一次**（React 加 px、Vue 不加）。

## 定案：横向定位模型 = 「flex 行 + 原生横向滚动」

`docs/analysis/table-virtual.md` §4。与上游的差异只在**滚动驱动方式**（上游 `marginLeft` 模拟 +
自绘 `ScrollBar`；本仓原生），**行的 flex 布局逐字一致**。`styles={{horizontalScrollBar}}`
不生效 ⇒ sticky 横向滚动条缺失（登记 COMPATIBILITY D126）。
