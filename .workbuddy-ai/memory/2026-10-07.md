### 📌 本轮踩到的坑（都是新的）

1. **`ERR_PACKAGE_PATH_NOT_EXPORTED` 是假警报** —— 用 `createRequire().resolve()` 探 **ESM-only** 包
   （`"type": "module"` + dist 里 `.cjs` = 0）必然失败：CJS 条件集是 `["require","node","default"]`，
   而 exports 只有 `types`/`import`。**字符串导出**（`./button/style.css`）却能过 ⇒ 这个「一半过一半不过」的
   差分就是判据。要用 `import.meta.resolve`（且**探针文件必须在仓库内**，放 `/tmp` 会解析到 `/tmp/node_modules`）。
2. **后台构建期间 `ls dist` 会看到中间态** —— 我在 dist 被重建时抓到「0 个条目 / MODULE_NOT_FOUND」，
   前后两轮结论矛盾。**结论：探测前先确认没有构建在跑。**
3. **D 差点只做 12/13**：`theme` 有 `ownBuildConfig: true` ⇒ 被共享配置跳过，而门禁里那句
   「产物已是模块结构」对 theme 是**假的**（dist 只有 4 文件 / 1 mjs）。⇒ **「不用共享配置」≠「不用 preserveModules」**，
   已写进 `scripts/unbuild-preserve-modules.mjs` 的注释。
4. **补 theme 后复测 ui 组件体积零变化**（divider/button/empty/color-picker/table 逐个 < 0.05 KB）
   —— ui 本来就整块消费 theme 的模块。**别把 1272.9→7.5 的功劳算给 D，那是 A 的**；
   D 的收益在**直接消费 foundation 包**的场景。
5. **B1 此前绕过 `scripts.build`**：硬编码裸 `unbuild`（不带 `--config`）⇒ D 实施后门禁**照样出单文件还全绿**。
   这是「门禁与发布命令不是同一条」的静默分叉，与 `ui-tree-shaking` 同源。已改为 `/bin/sh -c <scripts.build>`。
6. **`import * as all` 探深入口会留住整个模块的导出**（divider 29.9 KB vs 具名导入 7.5 KB）
   ⇒ 预算只认「根入口 + 具名导入」。
7. **budget 的条目要取并集**：`components.json`（72，含无自有 CSS 的 config-provider/watermark/
   auto-complete/time-picker）∪ `COMPONENT_STYLES`（69，含 components.json 没有的 `layout-sider`）= **73**，
   与 exports 的 JS 深入口数一致。只看任一个都留盲区。
8. 🚨 **`build.config.ts` 的类型错误只有 `pnpm run test:types` 抓得到** —— `vue-tsc --noEmit`
   不看它，而 vitest 的 `types` project 会把它当源文件收进去，而且报错算 **unhandled error**
   ⇒ **「Test Files 168 passed / Tests 2175 passed」全绿，但 exit=1**。看到这种
   「全绿却 exit=1」的组合，直接搜 `Unhandled Source Error`。
   本次具体错误：`applyPreserveModules(output: Record<string, unknown>)` 传给
   `options.output.map(...)` ⇒ TS2345（`OutputOptions` 没有 string 索引签名）。
   修法用 `type ElementOf<T> = T extends Array<infer U> ? U : T` 反推元素类型 ——
   ⚠️ **必须显式分发**：写成 `NonNullable<X> extends Array<infer U> ? U : X` 是错的
   （`NonNullable<X>` 不是裸类型参数、不分发 ⇒ 走 false 分支 ⇒ OutputOption 仍是
   `OutputOptions | OutputOptions[]` ⇒ `.map()` 又报错）。我第一轮就修成了这个错的版本，
   错误数从 1 涨到 2。

## 🔍 CSS 半边按需粒度核查（2026-10-07）—— **结论：我的怀疑不成立，但查出另一笔账**

起因：我怀疑 `dist/button/style.css` 212 KB 是 CSS 按需失效。**实测后推翻自己的假设**：

| 现象 | 结论 |
|---|---|
| 每份组件 CSS 都嵌 `BASE_CSS`（antd reset + 图标基线） | ✅ **刻意设计**。注释原文「每份组件 CSS 都自带，单引自足」「不然只引单个组件 CSS 也会退回 Times」；图标基线是第三次踩坑后收进全局的。代价：90 个重复块 ≈ **199.5 KB**（多为 ~150 B 小规则出现在全部 69 份里） |
| 每份组件 CSS 里 `apollo` / `ant` 各一份 | ✅ **刻意设计**。依据裁决 `prefix-cls-default`=A「默认 apollo，允许覆盖为 ant」——零运行时下不生成 `ant` 那份，承诺就是空的。文件注释明写「代价是 CSS 体积翻倍」 |

⇒ **两个都不是 bug，不要当成缺陷去改。** 教训：凭体积直觉怀疑之前，先 grep 生成点读注释 ——
我这次是对的，但差一点就改掉两个有事故依据的设计。

### 但查出一笔**负账**（已登记-red decision）

`ant` 那份占组件 CSS 总量的 **32.8%**（827.2 KB / 2522.2 KB），而它买到的能力**不完整**：
`packages/ui/src/__tests__/style-prefix.test.ts` 的 `KNOWN_GAPS` 现有 **24 个组件**的 `ant` 版类名数少于
`apollo` 版，其中 **7 个「规则体完全静态」（`gen(p)` 忽略了 `p`）几乎为空**：
`tabs` 885→1 · `input` 734→3 · `upload` 1051→1 · **`tooltip` 213→0** · `form` 322→2 ·
`pagination` 477→1 · `slider` 136→1 ⇒ 对这些组件，`prefixCls="ant"` **事实上没有任何样式**。
其余 17 个是「跨组件类名写成字面量」（`.apollo-icon` / `.apollo-dropdown` …）⇒ 部分不一致。

处置：登记开放决策 **`css-ant-prefix-cost`**（4 选项，推荐 C「按前缀拆两个文件」）；
`docs/KNOWN-ISSUES.md` §1.1 复建为该缺陷+决策指针。**等用户裁决再动 `STATIC_PREFIX_CLS`。**

快照，实测已变成 **24** —— 这类数字会漂移，已按实订正并写明「引用前去 KNOWN_GAPS 核对」。
