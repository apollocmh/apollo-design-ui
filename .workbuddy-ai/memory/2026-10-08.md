### ① `tree-select/checkable`：试了「`open` 受控展开」⇒ **此路不通**（已回退）

改法看起来与 `select/open`、`cascader` 同判（那两者都这么做且有效）。但加 `open` 后：
- 豁免**确实失效**了（变体终于产生差异）—— 说明思路方向对；
- 但**三视口全红**（mobile 1.469% / tablet 0.718% / desktop 0.383%，孤立重拍仍红）；
- 探针实测：antd 侧只渲染 **2 个父节点**，**展开的 leaf 1 / leaf 2 缺失**
  （`rc-virtual-list` 在「挂载即 open」下测量不全）⇒ 两侧**不可比**。

⇒ 已回退，并把这条实证写进 `duplicateAllow` 的 `reason`（**免得后人再试**）。
   真要覆盖勾选态，需要 harness 支持「真实交互后再截帧」。

### ② `pagination` 三个变体：试了「容器自适应」⇒ **效果无法证实**（已回退）

改法：`width: 640` → `width: '100%', maxWidth: 640`（desktop/tablet 下 `min(视口,640)=640`
**渲染不变**，只有 mobile 自适应）。理论上三视口里只有 mobile 会变。

结果：
- 实测**生效了**（mobile 下盒子 640 → 343px，`scrollWidth == width` 不再溢出）；
- 但 **`quickJumper`/`quickJumperButton`/`sizeChanger` 的 mobile 基线字节完全没变**
  ⇒ 三个变体**仍然互相同哈希** ⇒ **这个改动没有改善覆盖**；
- 反而把 `alignCenter` / `totalText` 的 mobile 基线改了（说明容器改动确实影响了别的变体）。

⇒ 按「**修复必须有可观测证据**」这条自定规矩**回退**（效果证不出，就不留）。

`tour/basic` · `modal/basic` · `transfer/basic` · `upload/basic`
