### ① 更正：`Enter` + **合法文本** ⇒ 提交（此前写错）

  ⇒ **测试是绿的，注释是错的**。

  「Enter + 合法文本 ⇒ 提交 + 关浮层」；PLAN/README 表述更正。→ PITFALLS **241**。

### ② S3 掩码模式（`format.type: 'mask'`）落地

用例：`mask-format.test.ts` **18 条**（node）+ `s3-mask.test.ts` **11 条**（jsdom）。

### ③ 本轮最有价值的一条（→ PITFALLS 242）

**Vue 没有 React 的 `restoreControlledState`**。掩码模式下上游把原生 `input` 事件做成
**空实现**，靠 React 在事件后把 DOM 值强制还原。Vue 不还原 ⇒ 必须**主动打一拍**
（`syncTick += 1`）触发重渲染，否则浏览器在 keydown **之后**落进 DOM 的原生字符会留在框里。

⚠️ 打拍还要打在**渲染函数读得到的地方**（`bind()` 里 `void syncTick.value`），
否则计数变了也不会重渲染 —— 这是本轮唯一「第一次写就错」的地方。

### 两个「范围专属」的发现（S4 的剩余项**不是**单值能做的）

| 项 | 为什么单值不可达 |
|---|---|
| `-input-active` | 上游 `Input.js` 的 `active = activeIndex === index`，而 `SinglePicker` **不传** `activeIndex` 给 `SingleSelector` ⇒ **单值恒不加**。⇒「分段高亮」本质是范围特性。 |
| `useFocusLock` 的强切换聚焦 | `forceFocus` 在单值下**恒为 `false`**：`submitField` 一定 `allFieldsTriggered` ⇒ 内部 `reset()` 把它抹掉。 |

⇒ 所以 S4 对单值**只剩** `-focused` + 失焦语义；其余随 S5 的 RangePicker 一起做。

### 🚨 本轮最有价值的一条（→ PITFALLS 243）

「失焦就关浮层」**不能照字面写**：点面板格子时输入框必然失焦（格子不可聚焦），
照字面写会让**第一次点日期就把浮层关掉** —— `showTime` 的确认制直接废掉。
上游靠**面板根是 `tabindex="0"` 的 div** + `relatedTarget` 包含判定兜住。
⚠️ 若面板根哪天丢了 `tabindex`，这条会**静默失效**，且「单值 + 无 showTime」时
**看起来是对的**。

## 收口：L7 构建门禁抓到一个**潜伏的跨包 ESM bug**

跑 `node tests/build/run.mjs`（权威构建门禁）时 **B8 红**：

```
❌ @apollo-design/ui  FAIL  B8  无法 import dist/index.mjs:
   Cannot find module '.../packages/picker/node_modules/dayjs/plugin/advancedFormat'
   imported from .../packages/picker/dist/index.mjs
```

- **根因**：`packages/picker/src/generate/dayjs.ts` 的 6 个 dayjs 插件导入**没带 `.js`**。
  dayjs 1.11.23 的 `package.json` **没有 `exports` 字段** ⇒ Node ESM 子路径导入必须给完整文件名。
  **Vite / vitest 会补后缀** ⇒ 开发与测试全程绿灯，只有真在 Node 里 `import()` 产物才炸。
- 🚨 **为什么一直潜伏**：`picker` **自己的 B8 是 `n/a`**（判据是「本包不含组件，无 SSR 冒烟对象」）
  ⇒ 它的 dist **从来没人 import**。直到 `ui` 里出现第一个消费 `picker` 的组件
  （本轮补上 `DatePicker` 的导出）才暴露。
  ⇒ **`tests/build` 对「不被任何人 import 的 foundation 包」有盲区**。→ PITFALLS **249**
- **修法**：6 处补 `.js`（+ 测试文件的 `updateLocale` 同步）；**单独重建 picker**
  （foundation 包改动必须单独重建，PITFALLS 176）。
- 验证：`picker` unit **287 passed**；`node -e "import('./packages/picker/dist/index.mjs')"` **OK**。

## G9 L6 二轮：3/21 → 12/21 exact（修掉三处真 bug）

起点是上一轮留下的「面板表头导航图标偏细偏浅」。**结论：那个诊断是错的** ——
真正的原因不是「1px vs 2px 描边」，而是**根本没渲染图标元素**。

### 一、探针（`tests/visual/debug/probe-datepicker-header.mjs`）

对拍表头按钮的 `outerHTML` + 计算样式 + 祖先链 + 命中测试 + 真点击。

- 🚨 **探针自己踩了坑**（PITFALLS 253）：React 侧 `getBoundingClientRect()` 全 `0×0`，
  但 `offsetWidth` 是 288 ⇒ **这两个数不一致 = 有 scale 变换**。真相是浮层停在
  `ant-slide-up-appear` 的**暂停首帧**（`transform: matrix(0,0,0,0,0,0)`）。
  `screenshotElement` 在截图前会剥掉 motion 相位类，我的探针**没做这一步**。
  ⇒ 顺手把剥类逻辑抽成 `stabilize.mjs` 的 **`stripMotionPhaseClasses(page)`**（已导出），
  `screenshotElement` 改为复用它。
- ⚠️ 连带教训：测量不对时**很容易得出错误对照**（我一度以为「React 也点不动」）。

### 二、三处真 bug

| # | 症状 | 根因 | 归属 |
|---|---|---|---|
| 1 | 表头箭头是**细字形 Unicode 字符**（`‹` `«`） | `PickerPanel` **少声明 4 个图标 props** ⇒ 被归进 `attrs` ⇒ `pickProps` 取不到 ⇒ `PanelHeader` 回退字符兜底 | `picker`（PITFALLS **250**） |
| 2 | 🚨 **面板在真实浏览器里完全点不动** + 无阴影 + `popup.container` 语义槽无宿主 | 浮层**缺 `-panel-container` / `-panel-layout`**（浮层根 `pointer-events: none`，**全库只有 container 重置成 `auto`**） | `ui`（PITFALLS **251**） |
| 3 | `classNames.popup.root`（**新 API**）静默失效 | 传的是原始 deprecated prop，不是上游那种**合并后**的 `popup.root` | `ui`（PITFALLS **252**） |

🚨 **三处都只有 L6 / 真浏览器能抓到**：
- #1：`aria-label` 才是可访问名 ⇒ L4 的 ARIA 比对照过；CSS 规则「确实存在」⇒ theme.test 也过。
- #2：jsdom 的 `trigger()` / `dispatchEvent` **绕过 `pointer-events`** ⇒ L1–L5 全绿。
- #3：既有用例只覆盖了 **deprecated** 写法，**新 API 一条都没有**。
