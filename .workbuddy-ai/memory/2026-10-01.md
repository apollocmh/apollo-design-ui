## date-picker · S3 掩码模式 + Enter 提交的更正（同一会话的第三段）

### ① 更正：`Enter` + **合法文本** ⇒ 提交（此前写错）

起手读 `Input.js` 时发现：`onSharedKeyDown` 的第一句是
```js
if (event.key === 'Enter' && validateFormat(inputValue)) { onSubmit(); }
```
`onSubmit` 一路接到 `SinglePicker` 的 `triggerConfirm('keyboard-submit')`
⇒ **提交并关浮层**。我先前把 keydown 链读成「两段」、漏掉了 `Input.js` 最前面这段，
于是在代码注释与 PLAN 里写了「Enter 不提交」。

- 两条既有 Enter 用例用的是**空输入框** ⇒ `validateFormat('')` 为假 ⇒ 从没走到提交分支
  ⇒ **测试是绿的，注释是错的**。
- 已修：`.vue` 的 `onInputKeydown` 补 ⓪ 段；`s2-typing` 用例改名 + 新增
  「Enter + 合法文本 ⇒ 提交 + 关浮层」；PLAN/README 表述更正。→ PITFALLS **241**。

### ② S3 掩码模式（`format.type: 'mask'`）落地

- `components/mask-format.ts` —— 上游 `MaskFormat.js`（81 行）的工厂 + 接口形态。
- `components/mask-input.ts` —— 上游 `Input.js` 的 `format` 分支
  （本地文本 / 字段选择区间 / keydown 的 Backspace·方向键·数字 / paste / 失焦还原）。
- `Selector.ts` —— 新增 `maskFormat` / `preserveInvalidOnBlur` / `validateFormat` /
  `onInputHelp` / `onInputSubmit` / `onInputText` 六个 prop + 两个元素 ref。
- `DatePicker.vue` —— `applyInputText` 抽出（普通 `input` 与掩码 `keydown` 共用）。

用例：`mask-format.test.ts` **18 条**（node）+ `s3-mask.test.ts` **11 条**（jsdom）。

### ③ 本轮最有价值的一条（→ PITFALLS 242）

**Vue 没有 React 的 `restoreControlledState`**。掩码模式下上游把原生 `input` 事件做成
**空实现**，靠 React 在事件后把 DOM 值强制还原。Vue 不还原 ⇒ 必须**主动打一拍**
（`syncTick += 1`）触发重渲染，否则浏览器在 keydown **之后**落进 DOM 的原生字符会留在框里。

⚠️ 打拍还要打在**渲染函数读得到的地方**（`bind()` 里 `void syncTick.value`），
否则计数变了也不会重渲染 —— 这是本轮唯一「第一次写就错」的地方。
