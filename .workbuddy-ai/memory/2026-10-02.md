## 本轮抓到的两个真 bug（都写进了 PITFALLS）

1. **`tabsBind` 的键名写错**：`{ defaultActiveTabKey: … }` —— `defaultActiveTabKey` 是 **Card** 的
   prop，**Tabs** 的是 `defaultActiveKey`。两个名字都合法 ⇒ **类型检查完全无感**；
   后果是**非受控页签静默失效** + DOM 上多一个 `defaultactivetabkey="b"`。
   被 L1 的「非受控：`defaultActiveTabKey` 生效」用例抓到（断言的是「哪个页签 active」，
   不是「prop 有没有传过去」）。⇒ **PITFALLS 300**。
2. **biome 的 `useImportType` 把 `import Tabs` 改写成 `import type Tabs`**：biome 看不到模板，
   而 `Tabs` 只出现在类型位置（`InstanceType<typeof Tabs>['$props']`）⇒ 判定 type-only。
   后果：模板解析不到组件，**静默渲染成原生 `<tabs>`**，只有 dev 一条 warn。
   ⇒ **PITFALLS 299**（附一条全仓判据：`grep -rn "^import type .* from '.*\.vue'"`）。

## 发现的两处跨组件问题（已登记，未擅自改）

- **`Tabs.vue` 的运行时 prop 声明 vs `TabsProps`**：回调参数类型系统性不一致
  （`unknown` / `Record<string, unknown>` vs `TabsEditEvent` / `TabsRenderTabBarProps`）。
  函数参数逆变 ⇒ 模板里 `v-bind="tabProps"` 必须过一次 `unknown`。⇒ **PITFALLS 301**。
- **`TabsProps['size']` 比 antd 窄**（`'small'|'default'|'large'` vs `SizeType`）：
  antd 的 `tabs` demo 里的 `tabProps={{ size: 'medium' }}` 在本仓**无法表达**。
  本仓 demo 改用 `size: 'default'`（在 Tabs 里与 `'medium'` 渲染完全相同）。
- 两处都写进了 `packages/ui/src/card/README.md` §5（第 6 / 8 条）。

## 需要记住的约定（新增）

- **新组件的 L6 变体要避开「静态帧测不到」的面**：`-hoverable` 的可见面只有 `cursor` /
  `transition` ⇒ 必然是空转变体，不给它独立 variant（归 L1 的类名断言与 L4）。
- **demo 里的外网图片一律换本地等价物**（data URI / 纯色块）；**未落地的组件**

- **L4 的 `it.each` 别用「长度不一致的元组数组」**：推断会退化成元组联合、回调签名对不上
