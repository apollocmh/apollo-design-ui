```js
const parseDate = (str, formatStr) => {
  const parsed = generateConfig.locale.parse(locale.locale, str, [formatStr]);
  return parsed && generateConfig.isValidate(parsed) ? parsed : null;
};
const validateFormat = text => {
  for (let i = 0; i < format.length; i += 1) {
    const singleFormat = format[i];
    if (typeof singleFormat === 'string') {      // ← 只支持字符串
      const parsed = parseDate(text, singleFormat);
      if (parsed) return parsed;
    }

```

⇒ 三条判据：**逐个 `formatList` 尝试**（这才是「format 传数组」的意义）·

### 🚨 又被实测纠正一次 —— 这次错的是**注释里的「为什么」**
我起草时断言「dayjs 的 `locale.parse` 在格式不匹配时返回**当前时间**（不是 `null`），
所以 `isValidate` 不可省」。**实测推翻**：
```js
dayjsGenerateConfig.locale.parse('en', '乱写的东西', ['YYYY-MM-DD'])  // ⇒ null
```
⇒ 不匹配时**本来就返回 `null`**。`isValidate` 真正挡的是 **Invalid Date**
（dayjs 对 `'not-a-date'` 给的是 Invalid 实例而非 `null`）⇒ 那一步是**双保险**：
在「已返回 null」的路径上冗余，但与上游逐字一致，且对 Invalid 路径必需 ⇒ **保留**。

⇒ 已记 **PITFALLS 233**：**注释里的「为什么」也是断言，也要跑一遍再写**。
这一路被实测纠正过很多次，但那些至少是「代码里的断言」—— 这次错的是「解释」。
