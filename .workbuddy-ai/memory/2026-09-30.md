   `interface.ts` 的 `DatePickerEmits` 是**同一契约的两处表达**。
2. 🚨 **TS2742（pnpm 严格 node_modules 的 dayjs 双副本）**：`packages/ui/node_modules/dayjs`
   与 `packages/picker/node_modules/dayjs` 各一份声明 ⇒ `DatePickerDate = PanelDateType`
   （picker 的那份）一进 `.vue` 的 setup 返回值，`vue-tsc` 就报
   `cannot be named without a reference to packages/picker/node_modules/dayjs`。
   ⇒ 解法是**统一到 ui 自己的 `Dayjs`**（结构等价，无私有成员）+ 一处集中的 `dayjsConfig` 断言。
3. 🚨 **`clearIcon` 缺默认值 ⇒ 清除按钮永不渲染**（3 条用例同时红）。
   `showClear` 的第一条条件就是 `isReactRenderable(clearIcon)`，回退链最后一位必须是
   `CloseCircleFilled`。本仓 `_internal/use-allow-clear` 有同判实现，但**入参是值不是 getter**
   ⇒ 放进 `computed` 会失去响应性 ⇒ 本轮在 `.vue` 里用 computed 重写并登记待统一。
4. ⚠️ **Vue 的 template 不支持 TS 断言**（`as X`）⇒ 需要收窄/断言的量必须先在
   `<script setup>` 里准备好（`builtinPlacements` / `popupAlign` / `popupMotion` 等）。
5. ⚠️ **`h(Component, props)` 的重载在 props 无索引签名时会解析失败**，
   报「missing $, $data, $props…」这种看着像组件实例的错 ⇒ 显式收窄 props
   （`as unknown as Record<string, unknown>`）+ 组件参数标 `as Component`。
6. ⚠️ **`useComponentConfig` 默认泛型是 `Record<string, unknown>`** ⇒ `context.classNames`
   等全是 `unknown`，会把下游一连串表达式推成 `unknown` ⇒ 显式收窄（本仓既有做法）。
7. ⚠️ 返回 `(string | undefined)[]` 的工具函数给 Vue 的 class / Trigger 的
   `popupClassName` 用会类型不匹配 ⇒ **在出口处过滤**（`getRootClassNames` /
   `getDropdownClassName` 已改返回 `string[]`）。
